# Tareas — 004 Diagnóstico y equipo inicial

- [ ] T1. Aprobar alcance del diagnóstico. **Hecho cuando:** propietario valida entrevista, informe, exclusiones, responsable de revisión y criterio comercial.
- [ ] T2. Resolver vertical de validación inicial. **Hecho cuando:** comparación documenta evidencia, acceso, frecuencia, impacto y opción piloto para cada candidato, con decisión fechada.
- [ ] T3. Completar Technical Blueprint. **Hecho cuando:** arquitectura, contratos versionados, flujo, permisos, datos, riesgos, costes y estrategia de evaluación tienen aprobación.
- [ ] T4. Crear prototipo sintético de cinco roles. **Hecho cuando:** procesa casos ficticios de extremo a extremo, se pausa en fallos y no ejecuta acciones externas.
- [ ] T5. Crear evaluación de calidad y gobernanza. **Hecho cuando:** cubre evidencia/confianza, datos incompletos, contradicciones, recomendación sin IA, privacidad, aislamiento y bloqueo preaprobación.
- [ ] T6. Validar entrevistas de problema. **Hecho cuando:** resultados consentidos y anonimizados permiten revisar patrones y voluntad de piloto sin compartir datos identificables entre empresas.
- [ ] T7. Preparar propuesta aprobable del piloto. **Hecho cuando:** alcance, exclusiones, precio, plazo, tratamiento de datos, métricas y riesgos constan como pendientes hasta decisión humana.
- [ ] T8. Implementar piloto real, si se aprueba. **Hecho cuando:** controles de identidad, organización, secretos, retención, auditoría, pausa/recuperación, revisión de seguridad y criterios de aceptación se verifican.
- [ ] T9. Revisar evidencia y decidir iteración. **Hecho cuando:** se registra continuar, ajustar o cerrar, con métricas y feedback.
- [ ] T10. Publicar documentación revisada en GitHub. **Hecho cuando:** diffs y validaciones revisados, commit acotado, push explícitamente autorizado y remoto verificado.
